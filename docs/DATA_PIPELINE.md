# 資料取得、時間對齊與分析方法

本文描述 **本專案目前的實作**，與 [EMG-Resistance](https://github.com/YuTzu2003/EMG-Resistance) 中由 HPF／官方匯出檔做離線分析的流程不同。此程式直接收集 Trigno SDK 串流、P715 BLE 封包及 FTMS Indoor Bike Data；不使用 LLM。

## 1. 三種資料如何取得

| 設備 | 來源與儲存 | 主要欄位 |
| --- | --- | --- |
| Delsys Trigno EMG | `StreamWorker` 從 Trigno SDK Server 讀取啟用 Slot 的原始樣本；以 SDK 回報取樣率寫入 `_EMG_*.csv` | `time_seconds`、每條已啟用 EMG 通道的原始值（V） |
| P715 踏板 | BLE Cycling Power Measurement `0x2A63` 通知；寫入 `_Pedal_*.csv`，並可匯出 FIT | 封包時間、瞬時功率 W、踏頻 rpm、左平衡百分比、估計左右功率 W、曲柄圈數及事件時間 |
| FTMS 訓練台 | BLE Indoor Bike Data `0x2AD2` 通知；寫入 `_Resistance_*.csv` | 原生阻力指令／回報、App 0–30 級、速度、功率、踏頻、心率、距離、能量等可用欄位 |

各 BLE 欄位是否有值取決於設備封包旗標。P715 的左右功率只在封包含有「以左腳為參考」的左右平衡時，由總功率乘百分比估算；**不是左右獨立扭力量測**。踏頻由相鄰曲柄事件的圈數與事件時間差計算；首筆或無有效事件差時留空。FTMS 缺少某欄時保留空值，不能視為 0。

## 2. EMG 基準與騎乘 RMS

1. 每個通道以實際 SDK 取樣率做因果濾波：預設 20 Hz 高通、450 Hz 低通，使用具有延續狀態的 biquad；可選 notch。截止頻率必須小於 Nyquist 頻率。這與 EMG-Resistance 的離線零相位 Butterworth 濾波**不是同一特徵方法**，不可直接混算兩專案數值。
2. 20 秒基準測量的前 10 秒捨棄，對後 10 秒全部有效濾波樣本計算 `baseline = sqrt(mean(filtered_emg²)) × 1000`，單位 mV。各 Slot 的基準、肌肉／側別、SID、取樣率、濾波參數、測量時間與使用者動作說明存於 AppConfig 的 `emg_baseline_settings.json`。
3. 騎乘中使用同一濾波器設定；每個通道取最近 200 ms 樣本做滑動 RMS，約每 200 ms 擷取一筆供摘要儲存。顯示 `RMS − baseline`（mV）、`(RMS − baseline) / baseline × 100%`，或 `RMS / baseline`（倍）。基準為零／過低、通道或 SID 不同、取樣率或濾波設定不同、資料不足時，比較值留空並標明原因。
4. 原始 EMG CSV 不被改寫。`*.analysis.json` 保存供介面回看的 RMS 時序與基準快照，不能取代原始訊號。

## 3. 時間對齊與踏板頻率

GUI 以一次騎乘開始時的 `time.monotonic()` 為共同起點，在收到各設備訊號時記下騎乘秒數。EMG 與訓練台在分析時建立**每秒檢視點**；各自找距離該點最近且相差不超過 2 秒的一筆，觀測起迄範圍外最多只容許 0.5 秒的邊界誤差。兩設備沒有實際重疊時不產生阻力／EMG 區段比較。無資料就留空，不把缺值補 0。`*.analysis.json` 內的 `aligned_1s` 是可重建的近似對齊視圖，並保留未重採樣的各裝置事件列。

若有共同可辨識事件，可在摘要頁手動設定「EMG 相對阻力時間偏移」；正值把 EMG 往較晚時間移動。偏移只作用於對齊視圖與阻力關係分析，不更動原始 CSV，也不改變單次 EMG 整體 RMS 統計。修改歷史分析檔時會儲存新的偏移及對齊結果。

**P715 封包頻率不參與 EMG／訓練台每秒對齊**。踏板功率、踏頻、左右平衡及曲柄圈數依自己的通知時間獨立統計與繪圖；不能把踏板接收頻率解讀為踏頻。三設備無共同硬體 trigger，目前的時間點是程式接收時間，含藍牙、SDK、執行緒及 GUI 排程延遲。手動偏移也只是事件參照校正，不能證明毫秒級神經肌肉延遲。

## 4. 單次騎乘分析

- EMG：每個偵測通道的平均／最大 RMS、對基準差值或倍數、前 1/3 與後 1/3 騎乘的平均 RMS。即使沒有可用基準，原始 RMS 摘要仍會顯示；基準比較欄留空。
- 踏板：平均功率、踏頻、左平衡、估計左右功率、曲柄計數變化；踏板頁與 HTML 報表另有功率區間、NP／IF／TSS、最佳 5／60 秒平均功率及資料涵蓋率，其計算依使用者設定 FTP。逐秒功率以該秒收到的有效封包平均計算；沒有封包的秒保留缺值，不當成 0 W。僅完整且連續的 30 秒視窗用於 NP；不足 30 秒不產生 NP／IF／TSS。全程涵蓋率低於 95% 時不產生 TSS，功率區間百分比只以有資料的秒數為分母。0 W 封包才計入零功率時間。左右平衡僅在 BLE 旗標指明左側參考時標示左／右；左右功率由總功率乘平衡比估算，並非獨立量測的踩踏相位或踏板中心偏移。
- 訓練台：指令等級、原生指令／回報阻力、功率、速度、踏頻、心率、距離與能量。各欄只用有效數字做統計。
- EMG × 阻力：以每秒近似對齊資料，列出每個回報阻力值區段的 EMG RMS、訓練台功率與踏頻；資料足夠且兩訊號都有變化時，計算各通道 RMS 與回報阻力的零位移 Pearson `r`。它只描述同時間共同變化，不是力量貢獻、因果或反應延遲。
- 資料品質：缺 EMG／踏板／阻力、無基準、基準不相容，以及 EMG 與阻力無重疊時間時，在摘要和 HTML 報表呈現提示。

## 5. 兩次獨立騎乘比較

第一次與第二次各載入一份 `*.analysis.json`。程式按 Slot 配對，並檢查肌肉名稱與左右側、感測器 SID、濾波設定、取樣率；不相容時只顯示原因。每個可比較通道顯示中位 RMS、P90 RMS、`P90 / 中位` 波動比、`第二次中位 − 第一次中位`（mV）及相對第一次中位的變化百分比。若兩次各自有有效基準，也會分別顯示 `中位 RMS / 該次基準`；不同基準不被當成相同量測條件。同名左右肌肉都有資料時，另列 `(右側中位 − 左側中位) / 兩側中位平均 × 100%` 的相對電活動差；不是左右實際力量差。

這些指標沿用 EMG-Resistance 對**活化振幅與波動**的描述方式；本程式目前的 P715 欄位沒有該專案使用的左右 crank 有號力量波形，因此不計算它的「逐圈活化形狀一致度」、左右腳獨立峰值事件或真正的左右肌力差。比較前仍需確認兩次的電極位置、皮膚處理、姿勢、阻力流程和實際踩踏任務相近；否則差值主要可能來自量測條件。

## 6. 輸出與限制

Each ride keeps its raw CSV files, information file, versioned analysis JSON, and a standalone HTML report with session settings, muscle trends, pedal and trainer summaries, statistics, synchronization details, and data-quality notes.
