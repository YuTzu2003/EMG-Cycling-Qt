# Issue：建立 SQL Server 復健騎乘分析資料庫，供手機與醫師查詢

## 需求背景

桌面程式已有 EMG、阻力計與踏板 CSV、FIT，以及包含時間序列的 `.analysis.json`。目前測試紀錄分散於檔案，手機無法按病人與日期查詢，醫師也難以比較相同條件下的歷次測試。需要一個用 SSMS 可建立的 SQL Server 資料庫，保存臨床追蹤所需的精簡結果與原始檔索引。

## 使用者故事

- 身為病人，我能在手機查看每次騎乘的完成時間、症狀、各肌肉 RMS 趨勢、功率、踏頻與左右差異。
- 身為主治醫師，我能查看每次測試的肌肉側別、基準值、阻力條件、資料品質、踩踏角度結果及跨次變化，並記錄判讀備註。
- 身為系統管理員，我能在 SSMS 建立資料庫，控制存取、備份及確認原始檔的位置。

## 第一階段範圍：資料庫設計與建置

- [x] 提供可在 SSMS 執行的 `database/001_create_emg_cycling.sql`。
- [x] 定義病人、測試、肌肉摘要、阻力階段、時間區間、踩踏角度與檔案索引的資料表及關聯。
- [x] 資料表保留左右側別、RMS 單位、UTC 時間、演算法版本與缺值資訊。
- [x] 腳本不刪除現有資料；可重跑；最後可查核資料表是否建立。
- [x] 提供 SSMS 操作與現有資料欄位對照文件。

## 第二階段範圍：桌面程式匯入與驗證

- [ ] 在使用者選擇啟用資料庫輸出後，將一次完成的測試以交易匯入；寫入失敗時保留原 CSV／FIT／JSON 並提示可重試。
- [ ] 可匯入既有 `.analysis.json`，重複匯入同一測試不產生重複紀錄；需明確定義歷史測試識別與去重規則。
- [ ] 匯入每條肌肉的錄製時名稱與側別、基準值、整次 RMS，以及前後段摘要。
- [ ] 對已觀測時間點產生每 5 秒趨勢，保留觀測秒數與有效 RMS 點數；不得把缺值當零。
- [ ] 依實際阻力變更建立階段摘要；只有具備有效角度分析的測試才建立角度資料。
- [ ] 在 SQL Server 測試資料庫驗證 5 分鐘、14 條肌肉的匯入與重新查詢；確認結果與原始分析檔一致。
- [ ] 明確記錄「200 毫秒 RMS 快照的區間平均」與原始波形重新計算 RMS 的差異。

## 第三階段範圍：手機查詢與醫師使用

- [ ] 後端 API 提供病人測試列表、單次摘要、肌肉趨勢、阻力階段與角度摘要。
- [ ] 病人只能查看自己的測試；醫師只能查看獲授權病人的資料；查閱及修改留下稽核紀錄。
- [ ] 手機只向 API 讀取需要顯示的資料，不直接存取 SQL Server 或完整原始 EMG 波形。
- [ ] 跨次比較標明測試姿勢、阻力、踏頻、基準方法與資料品質是否可比。

## 驗收範例

1. 在新的 SQL Server 執行初始腳本後，SSMS 可看到八個資料表；再次執行後，表與既有資料仍存在。
2. 一次只測 EMG 的測試沒有阻力與踏板時間列；未測的肌肉不產生 `SessionMuscles` 列。
3. 5 分鐘的 5 秒趨勢至多約 60 個時間區間；14 條肌肉至多約 840 筆肌肉區間列，實際筆數以有效資料為準。
4. 若踏板資料中斷，缺失區間不顯示為零功率；資料品質可追溯。
5. 從角度圖表點選「0° 附近」時，可查到肌肉、側別、階段、角度區間及其相對參考值。

## 明確不包含

本次提供的建庫腳本不會建立醫院正式病歷主檔、連接雲端、上傳既有病人資料或實作手機 App。這些需要資料來源、身分驗證與部署環境確定後另行實作。
